= Project Checkpoint: A CLI Tool

Time to put Part 2 together into something that runs. This checkpoint is a small, self-contained command-line guessing game, deliberately similar to the Rust Book's own first project (its guessing-game chapter) — it's a well-worn shape for a reason: it's small enough to finish in one sitting, and it naturally exercises functions, `let`, `cond`, recursion, and namespaces all at once.

This project is separate from `reading-list`, the app you deployed in <<ch-1-3-hello-production,1.3>> and will keep extending starting in <<ch-3-4-project-checkpoint-web-api,3.4>>. It doesn't get deployed, and it doesn't plug into that app. That's a deliberate choice, not an oversight: `reading-list` exists to prove you can *ship*; this project exists to prove you can *build*, by consolidating everything Part 2 just covered into one runnable tool without the extra ceremony of HTTP, Docker, or a hosting account. Keeping them separate means neither goal dilutes the other.

== Set up

Scaffold a new project the same way you did in <<ch-1-2-hello-program,1.2>>:

[source,shell]
----
clojure -Tnew app :name yourname/guess
----

You won't need the generated `greet`/`-main` pair or the placeholder test — this checkpoint replaces `src/yourname/guess.clj` from scratch. (The rest of this chapter uses `guess.core` as the namespace and drops the `deps-new`-style default of naming the main file after the project; feel free to keep either convention in your own copy.)

== The game

The rules: the program picks a random number between 1 and 100, the player guesses, and the program says "too high," "too low," or "you got it," repeating until the player finds it.

Start with reading and validating a single guess:

[source,clojure]
----
(ns guess.core
  (:gen-class))

(defn read-guess []
  (print "Guess a number between 1 and 100: ")
  (flush)
  (when-let [input (read-line)]
    (try
      (Integer/parseInt (clojure.string/trim input))
      (catch NumberFormatException _
        nil))))
----

A few things worth noticing, since each is a small pattern you'll see again and again in real Clojure code:

* `(flush)` after `print` matters here specifically because `print` (unlike `println`) doesn't force output to appear immediately, and we need the prompt visible before `read-line` blocks waiting for input.
* `when-let` binds `input` only if `(read-line)` returns non-`nil` — it returns `nil` at end-of-input (e.g. the user closes the terminal), and `when-let` gives us a clean way to short-circuit on that without an explicit `if` and a separate check.
* `try`/`catch` here is your first real use of the exception handling briefly introduced in <<ch-2-5-flow-control,Flow Control>> — turning a malformed guess like `"abc"` into `nil` instead of crashing the whole program. We come back to this in much more depth in <<ch-3-2-error-handling,Error Handling & Reading Stack Traces>>.

Now the game loop itself:

[source,clojure]
----
(defn play [target]
  (loop [attempts 1]
    (let [guess (read-guess)]
      (cond
        (nil? guess)
        (do (println "That doesn't look like a number, try again.")
            (recur attempts))

        (< guess target)
        (do (println "Too low!")
            (recur (inc attempts)))

        (> guess target)
        (do (println "Too high!")
            (recur (inc attempts)))

        :else
        (println (str "You got it in " attempts " guesses!"))))))

(defn -main [& _args]
  (println "Welcome to the guessing game! I'm thinking of a number from 1 to 100.")
  (play (inc (rand-int 100))))
----

`loop`/`recur` is Clojure's tail-recursive looping construct from <<ch-2-5-flow-control,Flow Control>> — `attempts` is the loop's only piece of state, incremented each time the guess is wrong. `cond` handles all four outcomes (invalid input, too low, too high, correct) as a flat list of condition/result pairs, falling through to the `:else` branch — no `recur` there — which is what actually ends the loop.

`(inc (rand-int 100))` produces a random integer from 1 to 100: `rand-int` alone returns `0`–`99`.

Run it:

[source,shell]
----
$ clojure -M:run-m
Welcome to the guessing game! I'm thinking of a number from 1 to 100.
Guess a number between 1 and 100: 50
Too high!
Guess a number between 1 and 100: 25
Too low!
Guess a number between 1 and 100: 37
You got it in 3 guesses!
----

== Testing without playing interactively

You don't have to actually sit and type guesses to check this works. Because `play` takes its randomness as a plain argument (`target`) rather than generating it internally, and reads input via the ordinary `read-line`, you can drive the whole thing from the REPL with `with-in-str`, which redirects stdin to a fixed string:

[source,clojure-repl]
----
user=> (require '[guess.core :as g])
nil
user=> (with-in-str "10\nabc\n80\n50\n"
         (g/play 50))
Guess a number between 1 and 100: Too low!
Guess a number between 1 and 100: That doesn't look like a number, try again.
Guess a number between 1 and 100: Too high!
Guess a number between 1 and 100: You got it in 3 guesses!
nil
----

This is worth pausing on: `play` didn't need any special "test mode" to be testable this way. Keeping the source of randomness and the source of input as arguments rather than baked-in calls is what made that possible — a small preview of the REPL-driven testing habits <<ch-3-3-testing,Testing>> covers properly.

== Try it yourself

* Add a maximum guess count, and print a "you lose" message (revealing the target) if the player doesn't find it in time.
* Let the player pick the upper bound instead of hardcoding 100.
* Track and print the best (fewest-guesses) result across multiple rounds, without exiting the program between them.
